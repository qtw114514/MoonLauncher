# 跨平台改造清单（WPF → Avalonia）

分支：`port`。目标：Windows / macOS / Linux 同一份代码。

本文分两部分：**已经落地的改动**，和**还没做的、按优先级排好的清单**。
每项都标了文件位置，可以直接照着做。

### 0.2 平台抽象层（新增）

- `Core/Platform.cs`：平台差异的唯一出口
  - `OsName` → `windows` / `osx` / `linux`（给 MC 版本 JSON 的 `rules.os.name` 用）
  - `OsArch` → Windows 走 `IsWow64Process2`，Unix 走 `RuntimeInformation.OSArchitecture`
  - `Memory()` → Windows `GlobalMemoryStatusEx` / Linux `/proc/meminfo` / macOS `sysctlbyname(hw.memsize)`
  - `JavaExeName` / `JavawExeName` / `ConsoleJavaPath()`
  - `NativesOs` / `RuntimePlatform(arch)` / `IsNativeLibrary()`
  - `OfficialGameDir` → `%APPDATA%\.minecraft` / `~/.minecraft` / `~/Library/Application Support/minecraft`
  - `UserDataDir()` → exe 旁不可写时的回退目录
  - `OpenFolder` / `RevealInFolder` / `OpenUrl` → `explorer.exe` / `open` / `xdg-open`
  - `MoveToRecycleBin` → Windows `SHFileOperation`、macOS Finder、Linux XDG Trash
  - `Protect` / `Unprotect` → DPAPI，非 Windows 返回 null（调用方退化为明文）
- `Core/PlatformEncoding.cs`
  - `LegacyAnsiEncoding`：Windows 上是 GBK(936)，Unix 上是 UTF-8
  - `ConsoleEncoding(javaMajor)`：Java 8 用系统代码页，Java 9+ 用 UTF-8
  - `ArgFileEncoding`：Java 9~17 的 `@argfile` 按平台默认编码读

  - 命令行过长时的 `@argfile` 兜底只在 Windows 触发
  - 自定义游戏窗口标题（`SetWindowText` + `MainWindowHandle`）只在 Windows 执行

### 1.2 机械转换规则（本次实际使用的）

XAML：

1. `xmlns` → `https://github.com/avaloniaui`，文件后缀 `.xaml` → `.axaml`
2. `Style="{StaticResource X}"` → `Classes="x"`
3. `RenderOptions.BitmapScalingMode` → `BitmapInterpolationMode`
4. `Visibility="Visible/Collapsed"` → `IsVisible="True/False"`
5. `Visibility="{Binding X, Converter={StaticResource BoolVis}}"` → `IsVisible="{Binding X}"`
6. `VirtualizingPanel.*` → 删除
7. `ToolTip="x"` → `ToolTip.Tip="x"`
8. `MouseDoubleClick` → `DoubleTapped`，`MouseUp` → `PointerReleased`
9. `AllowDrop/Drop` → `DragDrop.AllowDrop/DragDrop.Drop`
10. TextBox 的 `HorizontalScrollBarVisibility/VerticalScrollBarVisibility` → 删除
11. `Image Source="/Assets/x.png"` → `avares://MoonLauncher/Assets/x.png`
12. `BooleanToVisibilityConverter` 资源块 → 删除

code-behind：

13. `using System.Windows.*` → `Avalonia.*`（Controls / Input / Media / Threading / Interactivity）
14. `.Visibility = X` → `.IsVisible = X`（值用 bool）
15. `Style = S("X")` → `Classes = { S("X") }`（`S` 改为返回小写 class 名）
16. `Dispatcher.BeginInvoke` → `Dispatcher.UIThread.Post`，`Dispatcher.CheckAccess` → `Dispatcher.UIThread.CheckAccess`
17. `Pickers.PickFile(...)` → `await Pickers.PickFileAsync(...)`（方法要标 `async`）

### 1.3 运行时才暴露的两个问题

编译通过不代表能跑。实跑抓到两处：

- **可执行文件与数据目录撞名**：Unix 产物叫 `MoonLauncher`（无 `.exe`），便携数据目录也叫 `MoonLauncher`，
  `Directory.CreateDirectory` 直接抛 `IOException`。已在 `Paths` 里改成 `MoonLauncher-data`。
- **图标字体资源路径无效**：`avares://Avalonia.Themes.Fluent/Assets/SymbolThemeIcons.otf` 在 11.3.22 里不存在，
  启动即抛 `Could not create glyphTypeface`。已改成系统字体回退链
  （`Segoe MDL2 Assets, Segoe Fluent Icons, Apple Symbols, Noto Sans Symbols2, Symbola, sans-serif`）。

### 1.4 保留的功能降级（需要后续决定）

- **自定义主页不内嵌网页**：原 `WebBrowser`（IE 内核）在 Avalonia 没有对应物。
  现在只保留「打开原网页」按钮，卡片里提示去系统浏览器查看。
  要恢复内嵌需要引第三方 WebView（`WebViewControl-Avalonia` / CefGlue）。
- **游戏窗口标题自定义只在 Windows 生效**（`SetWindowText` + `MainWindowHandle`）。
- **图标码位**：`&#xE768;` 这类 Segoe MDL2 码位在 macOS/Linux 上会缺字形，显示为方框。
  建议逐步换成 `PathIcon` 或 emoji。

### 1.5 编译警告（无害，可后续清理）

- 9 个 `CS1998`：部分事件处理器标了 `async` 但没有 `await`（原 WPF 代码就是这样）
- 几个「`*.axaml` won't be reachable via runtime loader, as no public constructor was found」：
  带参构造的 UserControl 不能被运行时加载器实例化，但代码里都是 `new` 出来的，不影响

## 3. 已知行为差异（迁移后立刻能感知的）

- **`Encoding.Default` 语义变了**：.NET Framework 上是系统 ANSI（GBK），.NET Core 上恒为 UTF-8。
  所有原来靠 `Encoding.Default` 拿 GBK 的地方（Java 8 输出、`@argfile` 编码）都改成 `Platform.*Encoding`。
- **`ProcessStartInfo.Arguments` 在 Unix 上不可靠**：已全部改为 `ArgumentList`。
- **文件对话框变成异步**：`Pickers.PickFileAsync` 等返回 `Task<string>`，调用处要 `await`。
- **DPAPI 在 macOS/Linux 上不存在**：`Platform.Protect` 返回 null，`Settings` 退化为明文存储。
  账号令牌（`AccountStore`）同理，需要后续换成 Keychain / libsecret，否则令牌是明文落盘。
- **回收站实现换了**：Windows 从 `Microsoft.VisualBasic` 换成 `SHFileOperation`（等价效果）。
- **`\\?\` 长路径前缀不再加到 Unix 路径上**（加了会让路径失效）。
- **窗口标题自定义只在 Windows 生效**（`SetWindowText` + `MainWindowHandle`）。
